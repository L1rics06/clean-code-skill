## 开场寓言：写出你想在世界上看到的函数

Tony Van Eerd 的段子：新人 June 问导师"怎么读配置文件"，导师说"有个函数"。June 依次"找到" `getConfigFile`、`getConfigFilePath`……编译后全是未声明标识符。June："这些函数不存在啊。"导师："我知道。**我猜你得自己写了。**"

寓意：June 凭直觉说出的函数恰好处在**正确的抽象层级、易于拼装组合**——这就是"完美函数"的样子。

## 为什么需要函数

函数是人为叠加在硬件之上的抽象：CPU 只执行指令流加跳转，是编译器费力把函数调用翻译成指令和跳转。函数的核心价值是**管理复杂性**（局部推理、抽象、可测试、复用），而不是给代码新能力——全能全知者写 goto 汤也能达成一切目标。

- **局部推理**：只看函数体就能理解行为，外部修改不影响内部
- **可测试**：具备局部推理的函数只需在自身变化时重跑测试
- **复用**：常说的"重复 n 次再抽函数"，作者认为 **n = 1**——代码第一次写出来时就该考虑抽成函数

## 函数分类学：诚实（honest）vs 不诚实（dishonest）

传统"纯/不纯"二分法过度约束：原地 `sort` 改了输入却确定、可测试；`get_time()` 无副作用却依赖外部状态。

- **诚实函数**：**只通过函数签名访问外部世界**，调用者可通过构造参数完全控制其行为。涵盖大部分纯函数，也包括原地 `sort`（只改你明确交给它的内存）。
- **不诚实函数**：签名**不是**输入输出的完整描述。仍提供抽象与复用，但放弃了局部推理与可测试性。
- **诚实性会传染**：诚实函数不能调用不诚实函数。诚实函数在调用树**叶子**，不诚实函数靠近**根**。

### "函数生物学"（物种分类）

| 物种 | 特征 | 评价 |
|---|---|---|
| 真·纯函数 / 纯访问器 | 输入→输出，不改任何东西 | 诚实属的标准样本 |
| `vector::clear` / `remove_if` | 修改输入但对修改后的状态 100% 诚实且确定 | "漂亮的标本"；remove_if 是双输出通道（修改+返回值） |
| 不诚实访问器 | 名字像访问器，内部按全局状态过滤结果 | 作者上班踩过的坑：测试通过、别人调用就失败 |
| `draw_to_screen` 等越界交互 | 程序要做任何有趣的事就必须越过程序边界 | "标本很美，但它有牙齿"——严格约束使用位置 |
| 框架钩子（`update()`、`main`） | 抽象的是**调用点**而非实现 | 函数体保持最小，只做粘合 |

## 准则一：核心逻辑用诚实函数，最顶层注入不诚实

### 全排列程序

初版把诚实（`next_permutation` 循环）与不诚实（cout）混在 main 里，循环无法单测。重构：核心逻辑下推成函数，main 只做 IO。

- 换成文件 IO 版 main，"精神上还是同一个程序"——用控制台还是文件根本不是程序有趣的部分
- 常见重构模式：与其边算边执行不诚实函数，不如**先构建完整结果数据结构，再让不诚实代码事后处理**
- 结果太大（n! 内存）→ **依赖注入**：`for_each_permutation` 传入函数对象；Rust 中可用自定义迭代器，性能与灵活性兼得

### PRNG 案例（诚实性的教科书示范）

PRNG 整个机制从状态到输出全都是确定性的，唯一的"随机"来自种子——种子从"外面"（时钟/操作系统）拿。**坏例子不是 PRNG，是全局变量**：全局 PRNG 让函数与程序中所有其他用随机数的地方隐式拴在一起（线程推进、seed 被删、QA 无法复现）。

```cpp
// 焊死全局生成器 → 永远失去可复现/可测试/可分享 seed 的灵活性
void populate(int n) { std::srand(std::time(nullptr)); /* ... */ }

// 签名诚实 → 调用方决定：random_device{}() 每次不同；42 固定种子可复现
void populate(std::mt19937& rng, int n);
```

## 准则二：签名要对调用者有同理心

- 多参数+神秘尾部 `bool` → 打包成传参专用 struct 或用强类型
- 只打算循环就别要求 `vector<int>` → `span`（连续序列类型擦除）→ 只要"可迭代"。**别索要超出实际需要的保证；真需要强保证也别害羞**
- 反模式：只要两个字段却要求传整个大类 = "收银员要你交出整个钱包"
- **"必须先 A 再 B"**：A 返回空类型"回执"，B 必须持它才能调用：

```cpp
struct HandStamp { explicit HandStamp(std::unique_lock<std::mutex>&) {} };
auto stamp = lock(mutex);              // 不命名就拿不到回执 →
Data d = read_guarded(store, stamp);   // 不锁就编译不过；顺带消灭匿名锁立即析构的 bug
```

- **先调用你希望存在的函数**（呼应开场寓言）：公式想不起来就先 `bounce(velocity, surface)` 调用后实现。函数调用在**时间维度**上抽象实现细节
- **用类型编码不变量**：`NormalizedVec3` 薄包装，构造时保证已归一化、不可能构造非法实例；转回 `vec3` 应当容易（Liskov 替换意义上向上转换永远安全）。好处：函数内部不用管、责任上移给信息更充分的调用者、编译期强制契约、可做静态特化（`normalize(UnitVec3)` 塌缩成 no-op）
- 两个单位向量 cross product 结果必是单位向量——要不要编码进类型？"那条线在哪我不知道，但我看到就知道了"

## 准则三（黄金法则）：函数体每行处于同一抽象层级

统一了三条前人智慧：单一职责原则（Uncle Bob）、生产/消费数据分离（Tony Van Eerd）、非平凡循环体抽函数或用泛型算法（Sean Parent《No Raw Loops》）。

> 写函数就是搭砖，砖是已存在的低层函数。对某块砖"放大、摆弄、再缩小"应该是**一次函数调用**，绝不该发生在函数顶层。

**坏味道雷达：函数体里出现分段注释 = 混层级**。

### 大案例：资源查找函数的重构

```cpp
// 混层级：字符码小写循环（贴着砖抠）+ 手写二分查找（作者检查无数遍仍有 bug）
//        + 查不到 exit(1) + 类型检查 —— 四段注释 = 四个抽象层级
```

重构步骤：**列大纲**（转小写→查找→检查类型）→ 同缩进层级归入同一函数 → 二分查找改用 `std::lower_bound` → 最终识别出"小写化+二分查找"是在手工维护 ad hoc 数据结构 → 封装成 `CaseInsensitiveMap`：

```cpp
bool asset_has_type(std::string_view name, AssetType type) {
    const Asset* a = assets.find_ci(name);
    return a != nullptr && a->type == type;
}
```

要点：
- 函数体不必每行都是函数调用，可以"做事"（调算法、检查结果），但**当场打开算法的引擎盖**越界
- `CaseInsensitiveMap` 同时说清"存什么"和"怎么查"——作者的个人 map 命名模板
- 作者原话："我希望我所有的代码都长这样——它的实现停留在你看到函数名时脑子所处的抽象层级，读起来就是一串显而易见的高层步骤。"

## 总结

1. 保持系统诚实（可局部推理、可测试），在最顶层注入外部世界
2. 签名对调用双方都提供有用信息，不过度约束参数
3. 函数体停留在单一抽象层级 → 有组织、易理解、面对变化灵活
